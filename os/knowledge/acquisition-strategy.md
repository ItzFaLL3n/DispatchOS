# Acquisition Strategy — the layer under the playbook

Canonical. Source: `_source/client-acquisition-system.md`. This is the strategy;
`intake-playbook.md` is the tactical script that executes it. Alex Hormozi's
offer/lead frameworks + the Stone Method ascension model, both filtered through
the hard rules.

## Rule zero — where Hormozi is overruled

Hormozi's material assumes an offer that can promise and guarantee a measurable
business outcome. Where it conflicts with our rules, **our rules win, every
time.**

| Hormozi says | What applies here |
|---|---|
| Lead with the dream outcome, make a big claim | Never promise leads, calls, or rankings. Lead with the outcome *of the deliverable*, not a business result we don't control |
| Stack a guarantee that reverses all risk | Service guarantees only — no contract, cancel anytime, 14-day adjustment window, no hidden fees. Never a results guarantee |
| Use scarcity and urgency aggressively | Only genuine operational caps |
| Follow up relentlessly until they buy or die | One light follow-up, then let it sit. A stated deferral is respected, not chased |
| More offers, more often | One ask per message. Never bundle |

## The value equation, applied

Perceived value rises with **dream outcome** and **likelihood of achievement**,
falls with **time delay** and **effort required**. Most people inflate the
promise. The lever that actually works here is the bottom of the equation.

| Lever | State | Move |
|---|---|---|
| Dream outcome | "look as credible online as you are in the field" | Fine. Don't inflate into a lead promise |
| Likelihood of achievement | **Weak** — he's a stranger on Facebook | **This is the lever.** Proof beats persuasion |
| Time delay | Days from yes to live site | Strong. Lean on it |
| Effort & sacrifice | A few photos, a few questions, no money, no commitment | Very strong. Why the free build works at all |

**The whole game is likelihood.** Two things move it, nothing else:

1. **Delivered work you can show.** A screenshot of a real hauling company's
   real page beats any sentence about what you'd build. → build a one-screen
   proof page (a Dispatch OS page, not client-facing) of live URLs + before/
   after screenshots. It goes in the DM at the exact moment skepticism shows
   up, and nowhere else.
2. **Doing exactly what you said, on time, with no surprise ask attached.** The
   zero-ask check-in is the single highest-leverage credibility move in the
   sequence, because nobody else does it.

## The free build is a lead magnet

Solves one narrow problem completely, and in solving it makes the next problem
visible — naturally, not by design.

- **Solves completely:** they had no web presence (or a bad one). Now they have
  a real one they own.
- **Reveals:** it's on a `.vercel.app` subdomain — won't show up when someone
  in town searches; estimate requests land in an untracked Gmail inbox.

**The gap must never be manufactured.** Don't cripple the free site. Don't hide
the subdomain limitation. Build the best free site you can and the gap appears
by itself, because it's real. **Let them find it, don't point at it.**

## The offer stack — name the components

The $39/$49 tier already contains real components; they're just not named, so
they're not valued. When he asks what he's paying for, give the plain list (not
a hype stack):

**$39/mo:** site stays live & hosted · ongoing updates as the business changes
· separate service pages · ongoing SEO so the site can be found · job/customer
tracking dashboard · estimate requests in one place.
**$49/mo:** same, plus the domain handled entirely — registration, DNS,
renewal.

## Two options, never yes-or-no

The $39/$49 split changes the question from *"do I pay?"* to *"which one?"*.
Keep it. Never collapse to a single number. The genuine difference (self-manage
DNS + renewal vs handled) is a real reason to pay $10 more — say it plainly,
don't dramatize (`hard-rules.md` rule 7).

## Core Four — lead channels

| Channel | State | Next move |
|---|---|---|
| **Warm outreach** | Not running | **Biggest untapped one.** Ask a delighted free client for one introduction to another operator — a warm lead with a live reference attached |
| **Cold outreach** | Running — FB DMs to page owners | Constrained by account health. Keep it slow |
| **Free content** | Running — FB group posts, two-version format | The main engine. Scale by working more groups, not posting more in the same ones |
| **Paid ads** | Not running | Correct. Don't start until 2–3 clients are on one standardized system and close rate is known |

### The referral ask
Timing: at Phase 8, after the zero-ask check-in lands well — never the same
message. Separate touch, separate day. One ask, no incentive, no follow-up if
he doesn't bite.
> *"random question, you know any other guys in the area running something similar? been doing a couple of these builds and would rather work off someone knowing someone than cold messaging strangers all day"*

## Ascension (the Stone Method layer)

**Stop selling pieces.** Hosting at $39, GBP as a line item, review agent as
another — that's five invoices from one guy. They want one thing that works and
one bill.

```
free build          $0       →  proof, trust, a live site they own
hosting retainer    $39/49   →  the first yes. small on purpose
Growth Foundation   $197     →  hosting absorbed, GBP + CRM + missed-call text-back
Growth              $297     →  + review agent + lead follow-up
Full System         $799     →  + chat widget + full pipeline
```

$39 is not where the money is. **$39 exists to convert a free-build recipient
into a paying client** — a category change that makes every later offer a
different conversation. $0 → $39 is the hard step; $39 → $197 is a much smaller
psychological move than $0 → $197.

**Standardization is what makes this scale.** Once 2–3 clients in one niche run
the same setup, stop building custom — deploy a template with a different
business name. Same niche, new cities. This is what makes the Phase 4
site-builder agent worth building.

### Ascension triggers — the pipeline auditor surfaces any client whose notes contain one

| Signal | Points to |
|---|---|
| "how do I show up on Google" | GBP → Foundation |
| "I missed a call while I was on a job" | missed-call text-back → Foundation |
| "how do I get more reviews" | review agent → Growth |
| "how do I keep track of jobs" | CRM/dashboard → already promised, deliver it |
| "we're getting busier" | any tier — the money objection just weakened |

## The scoreboard — four numbers, reviewed monthly, don't add more

1. **Reply rate** — replies ÷ outreach touches. Does the post/DM copy work.
2. **Intake→delivery rate** — sites delivered ÷ intakes started. Are people
   lost mid-build.
3. **Retainer close rate** — paying ÷ delivered. The number that matters most.
   Becomes a signal at n=3.
4. **MRR** — the only number that compounds.

## Guardrails on changing the offer

- Do not redesign the offer before three clients have completed Phase 9.
- One live pricing experiment at a time (currently: Total Property Service,
  early disclosure — see `../casebook/total-property-early-disclosure.md`).

## Hot-path checklist

- [ ] Is skepticism showing? → send the proof page, nowhere else.
- [ ] Retainer question framed as two options, never yes/no.
- [ ] Offer components named as a plain list only when he asks.
- [ ] Ascension trigger in the notes? → surface it, don't pitch unprompted.
- [ ] Any instinct to change the offer? → not before n=3 at Phase 9.
